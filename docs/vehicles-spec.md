# איפיון: ניהול רכבי חברה (v2)

סטטוס: טיוטה מעודכנת לפי תשובות. סעיפים המסומנים ⏳ ממתינים להבהרה.

**החלטה מאוחרת (גוברת על כל מה שמופיע בהמשך):** אין תפקיד `fleet` נפרד. ניהול הרכבים נעשה על ידי תפקיד **מנהל** (`manager`), עם הרשאת קריאה וכתיבה מלאה. בכל מקום במסמך שכתוב "fleet" או "מזכיר רכבים", הכוונה למנהל. התראות והרשאות הצי חלות על כל המנהלים.

**חלוקת עבודה:** בצד ה-fleet (מזכיר רכבים) ממומשים רשימת הרכבים, כרטיס רכב, ייבוא, התאמת נהגים, ביטוח/טסט/מנויים/ק"מ, מסמכים, דוחות וניתוח AI, והתראות ל-fleet. כל מה שפונה לעובדים (מסך "הרכב שלי", טופס קבלה/החלפה/החזרה, דיווח ק"מ ותשלום דוחות על ידי העובד, התראות לעובדים) **לא נכלל** ויפותח בנפרד.

## 1. מטרות
- מקור אמת אחד לכל רכב: מסמכים, ביטוח, טסט, מנויים, דוחות, ק"מ והיסטוריית שיוך.
- לדעת בכל רגע מי אחראי על הרכב (קובע מי משלם דוח, נזק או תאונה).
- התראה לפני פקיעה או איחור, לא אחריהם.
- הכנסת נתוני דוחות ומסמכים בעזרת ניתוח AI של סריקה, עם אישור אנושי.

## 2. תפקידים והרשאות
תפקיד חדש `fleet` (בממשק: "מזכיר/ת רכבים"). נוסף ל-`profiles.role` במיגרציה, בדומה ל-`add_accounting_role`, עם פונקציה `is_fleet()`.

| | עובד רגיל | fleet (מזכיר רכבים) | משה (אישור ביטוח) |
|---|---|---|---|
| ראיית נתוני הצי (מסמכים, ביטוחים, טסטים, דוחות של אחרים) | ✘ | ✔ | רק הצעות ביטוח לאישור |
| קבלת רכב, הצהרה, החלפה, הזנת ק"מ | ✔ (טפסים בלבד) | ✔ | |
| יצירת רכב, העלאת מסמכים, שיוך מנויים | ✘ | ✔ | |
| אישור טופס הצהרה | ✘ | ✔ | |
| אישור הצעת ביטוח | ✘ | ✔ | ✔ |
| ייצוא | ✘ | ✔ | |

אכיפה ב-RLS ולא רק בממשק. נתוני רכבים מופרדים לחלוטין מאזור הנה"ח בשלב זה.

**הוחלט:** עובד רגיל רואה רק "הרכב שלי" והדוחות שלו (כולל העלאת אישור תשלום, שה-fleet מאשר). שאר המידע חסוי. הנהלה/מנהלים רואים הכל (קריאה). העלאת סריקת דוח: fleet בלבד.
בעיה לפתור ב-RLS: "הדוחות שלי" נקבעים לפי שיוך הנהג בשעת העבירה (`vehicle_assignments`), לא לפי הרכב הנוכחי.

## 2א. טופס הצהרה דיגיטלי (לפי הטופס מאילנית)
"הצהרה בדבר קבלת/החזרת רכב" – טופס אחד לשלוש פעולות: **קבלתי / החלפתי / החזרתי**.
שדות העובד:
- שם העובד (אוטומטי), נהג/ת קבוע/ה ברכב: כן/לא, תאריך, שעה, מקום (אוטומטיים עם אפשרות עריכה).
- סוג רכב: **קבוע** או **חלופי/זמני**; מס' רכב, סוג רכב, ק"מ קבלה.
- צ'קבוקסים: צילום רישיון רכב נשלח למשרד, תעודת ביטוח (עם העלאת תמונה).
- פרטי הרכב שהוחזר: מס' רכב, סוג, ק"מ החזרה.
- צ'קליסט החזרה: הסרת פסקל, הסרה/חסימת דלקן (חובה כשמתקבל רכב חלופי), ווידוא שלא נשאר ציוד ברכב.
- חתימה ותאריך (`SignaturePad`) + הצהרת האחריות לנזקים/דוחות/תאונות.

"לשימוש המשרד" (fleet בלבד): השכרה / ליסינג, וכן **עדכון מנויים**: כביש 6, מנהרות הכרמל, פנגו, דלקן, **טרפילוג** (נוסף לרשימה המקורית).
הטופס יוצר אוטומטית רשומת שיוך (`vehicle_assignments`) ורשומת ק"מ, כך שאין הזנה כפולה. הוא יוצא גם כ-PDF לארכיון.

## 3. מחזור חיי רכב
`צפוי להגיע` → `ממתין לאישור ביטוח` → `הגיע – ממתין למסירה` → `בשימוש` → `בטיפול` → `הוצא משימוש`

### א. לפני הגעה
1. fleet יוצר כרטיס רכב: מס' רישוי (אם ידוע), יצרן/דגם, בעלות, תאריך הגעה צפוי.
2. fleet מעלה הצעת מחיר מהסוכן (קובץ מהמייל) ← סטטוס "נשלחה לאישור".
3. משה ו-fleet מקבלים התראה, ואחד מהם לוחץ **אשר / דחה** (עם הערה). הפעולה נרשמת (מי ומתי). ההצעה נסגרת באישור הראשון, והשני רואה מי אישר.
4. אחרי אישור: fleet מעלה פוליסה (חברה, מס' פוליסה, תקופה).
5. תזכורת: רכב מגיע בעוד X ימים ואין פוליסה פעילה ← התראה ל-fleet ולמשה.
6. חסם: אי אפשר למסור רכב בלי פוליסה פעילה.

### ב. מסירה לעובד
1. העובד מדווח באפליקציה "קיבלתי את הרכב": זמן, ק"מ, תמונות מצב (מומלץ).
2. וידוא מנויים: העובד מצהיר שיש לו מנויים. אם לא, אזהרה "אין להיכנס לכבישי אגרה" והתראה ל-fleet.
3. טופס הצהרת רכב דיגיטלי עם חתימה (כמו `SignaturePad`). ⏳ תוכן הטופס מאילנית, ממתין. התראה ל-fleet לאישור.
4. fleet משייך מנויים: כביש 6, פנגו, חוצה צפון, מנהרות הכרמל, דלקן. לכל מנוי סטטוס ותאריך. אין מעקב עלויות.

### ג. בשימוש – החלפות
שימוש קבוע, עם החלפות תכופות במהלך היום, לכן המסך חייב להיות מהיר (3 לחיצות):
- "החלפת רכב": רכב (נבחר מהרכבים שלי), עובד מקבל, זמן (ברירת מחדל: עכשיו), ק"מ (אופציונלי בהחלפה קצרה).
- הצהרת אחריות חובה: העובד המקבל מסמן שהוא מודע שבכל נזק/דוח/תאונה בזמן ששויך אליו הוא נושא בעלויות על פי חוק. נשמר זמן ומשתמש.
- החזרת רכב ("סיימתי") סוגרת את השיוך.
- שיוך הרכב לא חופף: פתיחת שיוך חדש סוגרת את הקודם. דיוק עד הדקה, כדי ששיוך דוחות לפי שעת עבירה יהיה נכון.
- fleet יכול להשלים או לתקן שיוך בדיעבד (ביומן שינויים).

## 4. דוחות – עם ניתוח AI
**זרימה**
1. מעלים סריקה/צילום של הדוח (fleet; ⏳ או העובד עצמו).
2. Edge Function (`analyze-vehicle-document`) שולחת את התמונה למודל ראייה (Claude) ומחזירה JSON: מס' דוח, מס' רכב, תאריך ושעת עבירה, מקום, סוג עבירה, סכום, מועד אחרון לתשלום, רשות, ניקוד.
3. המערכת מציגה את השדות לאישור/תיקון של fleet לצד התמונה, עם סימון שדות בביטחון נמוך. **אין שמירה אוטומטית בלי אישור.**
4. חישובים אוטומטיים: התאמת הרכב לפי מס' רישוי; מציאת הנהג לפי לוח שיוכים בשעת העבירה; חישוב ימים לתשלום; סימון סכום מוזל/מלא אם מופיעים בדוח.
5. תשלום: **העובד משלם את הסכום שהרשות מציגה.** המערכת לא מחשבת ריבית בעצמה. אם הסכום גדל, מעדכנים לפי סריקה חדשה או הזנה ידנית, וההיסטוריה נשמרת.

**סטטוסים:** `חדש` → `הועבר לנהג` → `שולם (אישור תשלום מצורף)` / `בערעור`
**תזכורות:** X ימים לפני מועד, ביום המועד, ואז שבועית עד תשלום. נשלחות לנהג ול-fleet.

**הערות**
- אותו מנגנון AI יכול לנתח גם פוליסות, רישיון רכב וטסט (תאריכי תוקף) ולמלא את הכרטיס.
- מפתח API נשמר כסוד של Edge Function בלבד, לא בקוד הלקוח. בקשות מוגבלות למשתמש fleet.
- תוכן הסריקה (שם נהג, ת"ז, כתובת) נשלח לספק חיצוני. מומלץ לוודא מול הייעוץ המשפטי / מדיניות הפרטיות.

## 5. התראות

| נושא | טריגר | נמענים |
|---|---|---|
| ביטוח | 60/30/14/7 ימים לפני פקיעה, ואחרי | fleet, משה |
| טסט | 60/30/14/7 ימים לפני פקיעה, ואחרי | fleet, נהג נוכחי |
| דוחות | לפני מועד, ביום, ואז שבועית | נהג, fleet |
| ק"מ | ב-1 לחודש לכל מחזיק רכב; אם לא הוזן אחרי N ימים (הצעה: 3) ← התראה ל-fleet שפונה לעובד אישית | נהג, fleet |
| טופס הצהרה | לא אושר אחרי 48 שעות | fleet |
| מנויים | רכב נמסר ויש מנוי חסר | fleet |
| אישור הצעת ביטוח | הצעה הועלתה | משה, fleet |

ק"מ: רשומה חודשית (ק"מ, תאריך, מי הזין, תמונת לוח מחוונים אופציונלית). חסימת ירידה בק"מ (אלא באישור fleet) וסימון קפיצה חריגה. לשונית "לא דיווחו החודש" ל-fleet.

## 6. מסמכים ואחסון
Supabase Storage, bucket פרטי `vehicle-documents`, נתיב `vehicles/{vehicle_id}/{type}/{file}`, קישורים חתומים קצרי תוקף. מדיניות גישה: fleet בלבד (ועובד לטפסים שהוא עצמו מגיש). סוגים: רישיון רכב, ביטוח חובה/מקיף, הצעת מחיר, טסט, דוח, אישור תשלום, טופס הצהרה, טופס החלפה, חוזה ליסינג, תמונות מצב, אחר. לכל מסמך: סוג, תוקף (אם יש), מי העלה, מתי.

## 7. ייצוא
- רכב בודד: ZIP בתיקיות לפי סוג מסמך + אקסל מסכם.
- כל הצי: אקסל עם גיליונות (רכבים, ביטוחים, טסטים, דוחות, ק"מ, שיוכים), סינון לפי תקופה.
- דוח "פקיעות קרובות ודוחות פתוחים".

## 8. מודל נתונים
`vehicles`, `vehicle_insurance_quotes`, `vehicle_insurance_policies`, `vehicle_inspections`, `vehicle_toll_subscriptions`, `vehicle_assignments`, `vehicle_declaration_forms`, `vehicle_fines`, `vehicle_odometer_readings`, `vehicle_documents`, `vehicle_audit_log`. בכולן `created_by`/`created_at`. RLS על כולן.

## 9. מסכים (`src/features/vehicles/`)
- fleet: רשימת רכבים, כרטיס רכב (לשוניות), אשף רכב חדש, העלאת דוח + אישור ניתוח AI, דשבורד התראות/פקיעות, "לא דיווחו ק"מ", ייצוא.
- עובד (נייד): "הרכב שלי": קבלת רכב, החלפה מהירה, החזרה, הזנת ק"מ.
- משה ו-fleet: מסך אישור הצעות ביטוח.

## 10. שלבי פיתוח
1. תפקיד fleet + RLS, כרטיס רכב, מסמכים, ביטוח וטסט עם התראות, ק"מ חודשי + הסלמה.
2. מסירה לעובד, טופס הצהרה (אחרי קבלת הטופס), מנויים, אישור הצעה ע"י משה.
3. שיוכים והחלפות מהירות.
4. דוחות + ניתוח AI + שיוך אוטומטי לנהג + תזכורות.
5. ייצוא מלא.

## 10א. ייבוא טבלת המזכירה (חוברת1.xlsx)
מצורפת טבלה קיימת (~33 רכבים: משאיות, נגררים, רכבי ליסינג). עמודות: מס' רכב, סוג, שנת יצור, תאריך כניסה, דלקן, פסקל + מס' פסקל, כביש 6 (תאריך עדכון), מנהרות הכרמל, חוצה צפון, בעלות (ליסינג איגוד / פרטי מאיה / פרטי של אדם), סוכן ביטוח (גלובן / ביטוח ישיר), שם נהג.
- **ייבוא חד-פעמי** מהטבלה לטבלאות `vehicles`, `vehicle_toll_subscriptions`, `vehicle_assignments` (נהג נוכחי), עם מסך תצוגה מקדימה ותיקון לפני שמירה.
- נתונים לא אחידים בטבלה המקורית שיש לנקות בייבוא: תאריכים כמספרי אקסל או טקסט שבור (למשל `09-11-202`), `V` מול תאריך באותה עמודה, מס' רכב עם הערות (`*2323`), כמה ערכים בתא אחד (ביטוח מקיף + חובה), שדות נהג שהם כינוי ("משרד", "משאית קטנה").
- **מנוי פסקל** נוסף לרשימת המנויים (מס' מנוי נשמר, ולכן הוא שונה מ"V"). חוצה צפון גם כן.
- שדה "סוכן ביטוח" נשמר ברמת הרכב/פוליסה. שדות גיל נהג וותק ריקים בטבלה, ונשמרים רק אם נדרשים לביטוח.
- המערכת אחרי הייבוא מחליפה את הטבלה כמקור האמת.

## 11. שאלות פתוחות
הוחלט:
1. ✔ **ביטוח**: פרטי הפוליסה (חברה, סוכן, מקיף/חובה, תאריכי תחילה וסיום) מיובאים מסריקת הפוליסה בעזרת ניתוח ה-AI, באותו מנגנון של הדוחות (אישור fleet לפני שמירה). המערכת תציג "רכבים ללא פוליסה" עד להשלמה.
2. ✔ **ליסינג**: נשמרים תאריכי חוזה (תחילה/סיום) והתראה לפני סיום. "הוצא משימוש" כולל החזרת ליסינג, מכירה והשבתה, עם תאריך וסיבה.
3. ✔ **נגררים ומשאיות** במערכת באותו אופן. שדות ק"מ ומנויים אופציונליים לפי סוג רכב (נגרר: ללא ק"מ, ללא מנויים, ללא תזכורת ק"מ חודשית).
4. ✔ **רכב משרדי / חברה** (למשל "משרד", "חב' מאיה") הוא סוג מחזיק בפני עצמו. אין נהג קבוע, ולכן שיוך מתבצע בכל שימוש דרך טופס קבלה/החלפה, ודוחות בלי נהג בשעת העבירה מסומנים "ממתין לשיוך" אצל fleet.
5. ✔ **טופס ה-PDF** זהה לאקסל (אושר), ואין צורך בבדיקה נוספת.
6. ✔ טסט: fleet מזמין ומתעד. ברירות מחדל להתראות מאושרות.

אין שאלות פתוחות חוסמות לשלב 1.
